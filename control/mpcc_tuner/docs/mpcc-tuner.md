# MPCC 가중치 조절 화면

실행:

```bash
./scripts/mpcc_tuner.sh
```

브라우저에서 http://127.0.0.1:8765 를 엽니다. 기존 서버가 있으면 같은 주소로 접속합니다. 다른 포트는 `--port 8766`처럼 지정할 수 있습니다. 서버 종료는 실행한 터미널에서 Ctrl+C입니다.

## 사용 순서

1. 코스와 최대 속도, 가중치를 선택합니다. 기본은 편집 지도 · 양쪽 안쪽 코스, 4m/s, qc=0.1입니다.
2. 실행을 누르면 해당 설정을 고정하고 같은 출발 상태에서 새 시뮬레이션을 계산합니다. 계산 중 설정을 바꾸더라도 이미 실행 중인 계산에는 적용하지 않습니다.
3. 지도에서 기준 중심선·좌우 차량 중심 제한선, 기존 기준 실행, 새로운 차량 궤적, 현재 제어기의 예측 경로를 비교합니다. 예측 경로는 마지막 완료 제어 단계 시작 시점의 해이고 차량 표시는 그 단계 끝의 상태입니다.
4. 계산 후 재생과 시간 이동으로 각 구간을 확인합니다. 이 재생은 저장한 오프라인 계산을 보여줍니다.
5. qc만 0.1에서 1.0으로 바꿔 다시 실행해 비교합니다. 기준선은 같은 코스의 안정화 설정 실행(2026-09-16, qc=0.1, 최대속도4m/s)입니다. 속도도 바꾸면 같은 조건 비교가 아닙니다.

로그는 `results/건지광장/mpcc_tuner/<실행ID>/`에 저장합니다. request.json은 GUI 입력, job.json은 실행 상태, events.jsonl은 주행·예측 프레임, worker.log는 빌드/실행 로그입니다. runs/<UTC>/ 아래에는 기존 형식의 config.yaml, 생성 C solver, trajectory.csv, summary.json, simulation.npz와 실패 정보가 남습니다. 화면의 다운로드는 설정·요약·재생 프레임을 담은 JSON입니다.

## 해석 범위

- 실제 차량이나 VESC로 명령을 보내지 않습니다. Slash 평면 모델의 오프라인 실험입니다.
- 예정 장비 목록은 반영하지만, 총무게3.56kg·등가 모터전류±30A·마찰계수0.9는 미실측 가정입니다. 서스펜션·롤·피치·타이어 전기/열 과도현상은 모델링하지 않습니다.
- 가중치를 바꿔도 기준 중심선·좌우 경계는 바꾸지 않습니다. 최적화로 선택한 미래 경로와 차량이 따라간 궤적이 달라집니다.
- 지도에는 기록 경로 주변을 바닥으로 가정해 보완한 영역이 있습니다. 화면에서 실제 관측 바닥과 색으로 구분합니다.
- 최대속도 입력은 1–26.8m/s(약60mph)입니다. 이는 허용 상한이며 목표 속도나 실차 검증 범위가 아닙니다. 가상 진행속도 상한은 max(6, 1.5×최대속도)로 설정에 기록합니다. 배터리·기어·전류·타이어 모델에 따라 설정한 상한까지 도달하지 못할 수 있습니다.
- 입력 변화 벌점은 정규화된 변화량에 적용합니다. 항의 숫자만 직접 비교하지 마세요. terminal qc는 contour × terminal_contour_multiplier입니다.
- 계산 시간은 데스크톱에서 Controller.solve의 전체 시간입니다. 브라우저·HTTP·관측 데이터 저장·plant 적분은 포함하지 않습니다. UI 실행도 CPU 부하에 영향을 주므로 20ms 이내라는 결과는 실시간 보장이 아닙니다.
- 실패 또는 중지한 실행은 완료 랩으로 취급하지 않습니다. 그때까지 계산한 상태와 이유를 보존합니다.
- MVP는 한 번에 한 실행만 허용합니다. 중지 버튼은 다음 계산 경계에서 반영됩니다. solver 빌드 중에는 중지가 지연될 수 있습니다.

## MVP 검증 기록

기본 qc=0.1 실행은 기존 상태·입력과 일치했고 43.24초/최대22.3cm, qc=1.0은43.46초/최대8.8cm였습니다. 실제 브라우저에서 qc=0.3 실행·도중 입력 수정 격리·예측 표시·재생·기록 불러오기·JSON 다운로드를 확인했습니다. 중지는 부분 결과를 보존합니다. 상세 근거: results/건지광장/mpcc_tuner/mvp_verification.json 및 mvp_screen.png. 단위 테스트16개, 기존 acados17개·Slash4개 회귀 테스트 통과.

## 속도 입력 상한 변경 (2026-09-16)

초기 GUI 제한8m/s를26.8m/s(약60mph)로 확장했습니다. 기본 실행값4m/s와 물리 파라미터는 유지합니다. 현재 가정의3S·기본기어·등가30A·저항 모델에서 무부하 환산속도는21.801m/s, 평지 직선의 전류 최대 조건 평형속도는9.621m/s입니다. 이는 실제 차량 최고속도 측정이 아닙니다. 계산 근거는 results/건지광장/mpcc_tuner/speed_limit_model_check.json에 저장했습니다.

실제 브라우저에서26.8m/s 상한을 입력·전달·저장하는 것을 검증했습니다. 기본 가중치로 시도한 실행은 step18에서 acados status4로 종료됐습니다. 상한 설정 지원과 해당 조건에서의 최적화 수렴은 별개이며, 실패 상세는 speed_limit_gui_verification.json과 해당 실행 로그에 보존했습니다.

## 기본값 주변 실행 실패 개선 (2026-09-16)

이전 GUI는 원래 수치 설정(LM=1e-6)에서 qc=0.03266이나 속도 상한6.3m/s만 적용해도 출발 직후 QP 계산이 실패했습니다. GUI 전용 `src/aac_2026/control/mpcc_tuner/config/mpcc_tuner.yaml`에서 Levenberg–Marquardt 정규화를0.1로 높여 한 번의 RTI 갱신이 지나치게 커지는 것을 억제했습니다. 차량 모델, 사용자 목적함수 가중치, 물리·트랙 제약과 판정 허용오차는 유지했습니다. 정규화도 유한 횟수 RTI의 실제 궤적에는 영향을 줍니다.

3개 코스의 기본 기준선을 동일 설정으로 다시 계산했습니다: `results/건지광장/mpcc_tuner_baseline/20260916_stable_rti/`. 이전 기록은 보존하며, 화면에 계산 설정이 다른 기록임을 표시합니다.

양쪽 안쪽 코스에서 qc=0.03266(42.86초), 속도 상한6.3m/s(28.36초), 속도 상한26.8m/s(24.34초), ql=500, 진행 보상0.04, 조향 변화 벌점0.5가 각각 완주했습니다. 한 번에 한 입력만 바꾼 시험이며 모든 조합의 성공을 보장하지 않습니다. 26.8m/s 상한 시험의 실제 최대속도는9.177m/s입니다.

qc=0.001343 및0.0002667은 출발 직후 QP 실패 대신13.12초 부근에서 경계 위반으로 중단됐습니다. 약2.6mm 위반도 기존2mm 허용오차를 초과하면 실패 처리합니다. 아주 작은 가중치에서도 무조건 완주하도록 제약을 완화하지 않습니다. 화면은 경계 초과와 최적화 계산 실패를 구분합니다.

실험·비교·GUI 확인 근거: `results/건지광장/mpcc_failure_analysis/20260916_regularization/`. 현재 GUI 단위 테스트17개 통과. 계산 시간은 데스크톱에서 관측한 값이며 Jetson 50Hz 실시간 보장이 아닙니다.

## 편집 지도 연결 (2026-09-19)

기본 코스 `edited_inner`는 `results/건지광장/map_edit/20260917_inner_focus/`의 편집 주행 영역과 `track_both_inner`를 함께 사용합니다. 화면에서는 **편집 지도 · 양쪽 안쪽**으로 표시합니다. 이 지도는 사용자가 지정한 고립 점들을 제거한 복사본으로, 바닥과 큰 구조물을 보존했고 기존 가정 바닥을 포함합니다. 기존 대칭 경계·편측1m 상한은 유지합니다.

기존 `outer`, `left_inner`, `both_inner`는 **이전 지도**로 이름만 구분했습니다. 이 코스와 저장된 이전 주행 기록을 선택하면 원래 v5 지도가 표시됩니다. 코스별 지도 URL이 달라서 새 지도와 이전 궤적을 잘못 겹치지 않습니다. 지도·중심선 경로·기준 실행은 `tools/mpcc_tuner/config.py`의 등록 코스로 관리합니다.

새 지도 기준 실행: `results/건지광장/mpcc_tuner_baseline/20260919_edited_inner/04_edited_inner/`. speed4m/s, qc0.1, SQP_RTI/LM0.1에서43.12초 완주. 차량 중심 경계·지도·footprint 침범0. 이전 기준43.22초와 비교하면 변화는 작습니다. 물리 모델·가중치·solver 설정은 그대로이며 입력 지도/중심선만 달라졌습니다.

검증 근거는 같은 baseline 상위 폴더의 `comparison.json`, `gui_verification.json`, `gui_edited.png`에 있습니다. GUI에서 새 코스와 이전 기록을 전환하고 새 실행·재생을 확인했습니다. GUI19개, acados17개, Slash4개 테스트 통과. 기준선 비교는 같은 코스의 기본값 결과이며, 편집 전후 비교는 코스 선택으로 전환합니다.
