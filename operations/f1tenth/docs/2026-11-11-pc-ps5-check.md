# PC에서 PS5 구동·정지 명령 검증 결과

2026-11-11. VESC·차량 없이 PC의 PS5 입력과 ROS 미리보기 출력을 검증했다.
물리 직렬 장치를 컨테이너에 전달하지 않았으며 모터·조향 서보를 구동하지 않았다.

## 요청한 네 가지 작업

| 항목 | 결과 |
|---|---|
| PS5 입력 → 전후진·정지 명령 | 실제 오른쪽 스틱으로 양방향 명령 확인 |
| R1 해제·×·입력 손실 시 명령 0 | 실제 패드 버튼과 USB 분리 시험 통과 |
| × 또는 입력 손실 후 재허용 필요 | ○ 없이 R1+스틱을 움직여도 0, 새 ○ 이후에만 명령 허용 |
| VESC 없는 미리보기·로그 검증 | 전부 미리보기로 실행, 원본 로그와 요약 저장 |

## 환경과 코드

- PC: Ubuntu 24.04.5 x86_64, Docker 내부 Ubuntu 22.04 / ROS Humble.
- 이미지: `aac-f1tenth-manual:humble-pc`.
- 소스: `/home/irdl4/.cache/codex-worktrees/aac-manual-20261111`.
- PC 작업 결과: `/home/irdl4/f1tenth_manual_pc_ws`.
- 패키지 6개 PC 빌드 성공, 기존/PC 프로필 포함 자동 테스트 18개 통과.
- 젯슨과 PC의 SDL 매핑이 달라 PC용 `config/manual.pc.yaml`을 추가했다.
  PC는 ×=b0, ○=b1, R1=b5, 오른쪽 Y=a4, 왼쪽 X=a0이다.
  젯슨 기본값은 유지하며 `F1TENTH_GAMEPAD_PROFILE`로 PC 입력 설정만 덧씌운다.

## 실제 패드 시험에서 확인한 것

- ○를 누르고 R1을 유지한 채 오른쪽 스틱 위/아래 → 양방향 명령.
  명목 속도 명령은 ±0.3, ERPM 미리보기는 약 ±1384.2였다.
  이 숫자는 실제 차량 속도를 측정한 결과가 아니다.
- 스틱이 끝까지 기울어진 상태에서 R1 해제 → 명령 0.
- 비영점 명령이 나오던 중 × → 명령 0.
- × 이후 ○ 없이 R1+스틱 재조작 → 명령 0 유지.
- 새 ○ 이후 R1+스틱 → 다시 비영점 명령 허용.
- 명령이 나오던 중 PS5 USB 분리 → 최종 중립 Joy 메시지가 들어온 뒤 명령 0 유지.
  물리적으로 케이블을 뽑은 시각은 직접 기록하지 않아 정확한 분리-정지 지연은
  측정하지 않았다. 입력 메시지 만료 0.3초 로직은 자동 시험으로 별도 검증했다.
- 재연결 시 제어 노드는 재시작하지 않고 입력 리더만 다시 열었다.
  ○ 전의 R1+스틱 입력 1385개 동안 출력 0 유지, 새 ○ 이후 명령 재허용을 확인했다.

## 남은 제한과 실차 작업

**현재 Docker 구성에서 USB 재연결의 자동 입력 재개는 완성되지 않았다.**
이번 시험에서는 입력 노드를 다시 열어 복구했다. 분리 중 정지와 재허용 차단은
검증됐지만, 무인 자동 재연결까지 검증한 것으로 해석하면 안 된다.

VESC 연결·설정 재확인, 조향 전원/신호/중심/끝점, 실제 모터 구동과 제동 거리,
실제 VESC USB 분리, 젯슨 실물 연동은 별도 하드웨어 시험으로 남아 있다.
