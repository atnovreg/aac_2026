## 4. 부탁할 작업 순서와 완료 기준

### A. PC 실행 환경과 재현 가능한 빌드

현재 스크립트는 `/opt/ros/humble/setup.bash`를 사용합니다.
PC는 Ubuntu 24.04이고 기존 F1TENTH Docker 구성은 Jazzy입니다.
추가 작업으로 Ubuntu 22.04 + ROS Humble 전용 이미지를 준비하고 PC 빌드·시험까지
완료했습니다. 이 결과는 `aac-f1tenth-manual:humble-pc` 환경 기준입니다.
기존 Jazzy 구성에서의 실행은 검증하지 않았습니다.

의존성은 README를 따라 설치하고, 컨테이너 사용 시 PS5와 VESC의 장치 접근,
input/dialout 권한 및 USB 재연결을 확인해주세요. CPU가 다른 장비 사이에는
소스·설정·설치 절차를 옮기고 `build/install/log`와 ARM용 의존 패키지는 재사용하지 않습니다.

캐시 worktree에서 스크립트를 실행할 때는 `F1TENTH_WS`를 명시해야 합니다.
기본 계산은 저장소가 `<workspace>/src/aac_2026`에 있다는 가정입니다.
컨테이너라면 컨테이너 안의 경로를 기준으로 지정해주세요.

완료 기준: PC에서 선택 패키지가 빌드되고 기존 15개 시험이 통과하며,
다른 사람이 설치·빌드·미리보기를 재현할 수 있습니다.

### B. PS5 입력을 먼저 미리보기로 확인

목표 조작은 ○=주행 허용, R1 유지+오른쪽 스틱 위/아래=전후진,
왼쪽 스틱 좌우=조향, ×=정지 및 허용 해제입니다.

현재 젯슨에서 읽은 매핑은 ×=b1, ○=b2, R1=b5, 왼쪽 X=a0, 오른쪽 Y=a5입니다.
**a4는 놓았을 때 +1인 트리거**이므로 이전 PS4 기본 매핑을 그대로 쓰면 위험합니다.
PC에서도 SDL 장치명과 실제 버튼/축을 확인하고 필요 시 설정만 조정해주세요.

`manual.sh dry-run`으로 시작합니다. 실제 장치가 연결되어도 이 모드는
VESC 드라이버를 띄우지 않습니다. 기존 일반 `joy_control.launch.py` 대신
이번 수동 전용 구성을 사용해주세요.

완료 기준: 허용 전에는 명령 0, 올바른 스틱 방향, R1 해제/×/입력 만료 후
정지 명령, 입력 손실 후 새로운 ○ 누름이 있어야 재출발합니다.

### C. VESC 상태와 구동·정지 확인

VESC 전원 및 PC USB를 연결하고 `manual.sh check`로 채널 117, 전압·온도·오류를
확인해주세요. USB by-id 이름은 듀얼 채널을 구별하지 못하므로 ID를 확인해야 합니다.
이 검사는 모터 설정 저장값이나 펌웨어 버전을 검증하지 않으므로, VESC Tool에서
전원 재투입 후 저장값과 펌웨어 5.2도 따로 읽어 확인해주세요.

**아래 실차 구동·정지 시험은 사용자 담당입니다.**
차를 안정적으로 받치고 구동 바퀴를 띄운 다음, 직접 관찰하면서
저속 전진·후진과 다음 정지 동작을 하나씩 시험합니다:

- R1 해제, × 버튼.
- PS5 연결 끊김, 제어 프로그램 종료, VESC USB 분리.
- 복구 후 저절로 재출발하지 않음.

현재 명목 속도 상한은 약 ±1384 ERPM, ROS 드라이버 상한은 ±2000 ERPM입니다.
설정의 0.3 m/s는 보정 전 변환값으로 실제 지상 속도가 아닙니다.
현재 `drive --wheels-up`은 바퀴를 띄운 시험용이며 조향 출력은 계속 차단됩니다.
직접 launch의 drive 모드를 실행하면 래퍼의 사전 검사를 건너뛰므로 래퍼를 사용해주세요.

완료 기준: 버튼/프로그램/통신 손실별로 실제 구동력이 사라지고 바퀴가 멈추는
모습과 소요 시간을 기록합니다. 공회전 정지 결과와 실제 지상 제동 거리를 구분합니다.

### D. 조향 하드웨어와 보정

먼저 서보 모델, BEC 출력 전압·전류, 커넥터 핀 배열, 공통 접지와 PWM 출력
경로를 확정해주세요. VESC의 펌웨어 5.2에서 필요한 서보 출력이 실제로 가능한지
확인해야 하며, ROS에 서보 토픽이 있다는 것만으로 지원을 판단하지 마세요.
지원되지 않으면 별도 PWM 출력 장치 등 필요한 구성을 정리해주세요.

현재 변환기는 `/manual/servo_preview`에만 발행하고 드라이버는
`/manual/disabled/servo`를 듣습니다. `servo_min=servo_max=0.5`이기도 하므로
배선만 연결해도 조향이 되는 상태는 아닙니다. 출력 경로를 확인한 뒤 작은 범위부터
중심·방향·좌우 끝점을 보정하고, 그 결과로 라우팅·계수·범위를 수정해주세요.

완료 기준: 스틱을 놓으면 직진 중심, 좌우 방향 일치, 끝점에서 링크의 기계적
걸림이나 서보가 계속 힘으로 버티는 현상 없음, 입력 손실 시 조향 동작도 정의·검증됩니다.

### E. 지상 시험과 젯슨 이전

구동·조향·정지 확인 후 통제된 공간에서 저속 지상 시험을 수행하고 실제
제동 거리와 하중에 맞는 제한값을 확인합니다. 구동·정지 시험은 사용자가 맡고
조향 담당자가 연결·보정 결과를 인계합니다. 이후 같은 소스를 젯슨에 옮겨
ARM용으로 다시 빌드하고 USB·PS5 매핑 및 전체 정지 시험을 반복해주세요.

최종 결과물은 **소스와 설정, 양쪽 설치/빌드/실행 명령, 배선도 또는 연결 사진,
변경한 VESC 값, 실제 시험 결과와 미확인 항목**입니다.
자동 실행 시에는 정지/미허용 상태로 시작하고, 사용자가 ○를 눌러 허용한 뒤
R1을 유지해야 움직이도록 해주세요.
